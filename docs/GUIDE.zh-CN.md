# 使用与权限

## 打开和记录

启用后，从 Hermes 的 Jot 导航、右侧面板、输入框图标或命令面板打开。笔记可以直接输入普通文档；无需先学 Markdown。文件夹完全可选，名字由用户决定。

“最近”显示置顶笔记和最近修改的几条；“全部”可以持续滚动。搜索同时查标题和正文。修改时间、创建时间、标题排序，以及列表宽度和隐藏状态是本机偏好，按连接和 profile 隔离。

## 保存与多人操作

输入后自动保存，也可以按 ⌘S / Ctrl+S。版本冲突会保留人工草稿，不直接覆盖服务器上的更新。从面板展开到完整工作台时会带上当前草稿。两处对相同内容的重复保存会确认同一已保存版本；不同的修改仍保留冲突保护。

这里的协作是人与 agent 共用同一份笔记，不是云同步或多人实时编辑服务。多个窗口仍通过版本检查保护提交。

已打开的随记面板会在笔记变化时刷新：Hermes 的插件事件会通知每次保存，包括 agent 的修改。另有每 30 秒一次的检查，覆盖事件无法通知的情况（例如从消息网关调用的工具）；不支持插件事件的旧版 Desktop 仍每 3 秒检查一次。笔记库没有变化时，检查无需启动笔记引擎。

## 附件

单个文件最多 20 MiB；每次最多 20 个文件；每个 profile 的附件库上限为 500 MiB / 1,000 个文件。格式不限于图片或 PDF，但图片和 PDF 会按实际字节识别，避免把伪装文件当成图片展示。

PNG、JPEG、GIF、WebP 可在笔记中显示。图片每边最多 10,000 像素，总计最多 4,000 万像素。附件不做全文索引或 OCR。

附件面板提供内嵌显示、Hermes 文件预览入口、下载和默认应用打开。默认应用打开的是管理副本，外部修改不会自动写回笔记。默认应用运行在 Hermes 后端所在的电脑；无图形环境时使用下载。

删除正文里的附件卡片不会立即删除原文件。永久删除笔记或清空回收站时，只清理没有被其他笔记引用的附件。

## 导入

“排序与选项 → 导入笔记…”接受 `.md`、`.markdown`、`.txt` 和 `.zip`，可以一次选择多个文件。笔记会放进当前查看的文件夹，否则保持未分类。

- Markdown 保留标题、列表（含嵌套和编号）、待办、引用、代码、分隔线、表格、粗体、斜体、删除线、行内代码、链接、下划线和随记调色板颜色。开头的 `# 标题` 会成为笔记标题，否则使用文件名。开头的 front matter 会被去掉；双链和其他不支持的语法保留为文字。
- ZIP 中每个顶层文件夹会成为随记文件夹（同名文件夹会复用），更深的文件夹并入所属的顶层文件夹。笔记链接到的图片和文件作为附件导入，其他文件列为已跳过。
- 随记自己导出的 Markdown 整库可以连同文件夹、图片和文件附件一起导回。导出不包含置顶、创建与修改时间、回收站、AI 修改标记与撤销记录、保留的草稿；合并单元格的表格会以文字导回。
- 限制：单个导入文件 100 MiB；每个 ZIP 最多 2,000 篇笔记、1,000 个附件；单篇笔记 4 MiB。附件和笔记库本身的上限仍然适用。无法读取的文件会列出，其余照常导入。

## 导出

- 当前笔记：TXT、Markdown、PDF、Word（DOCX）。带附件的 Markdown 导出为 ZIP。
- 整库／当前文件夹：按文件夹整理成 ZIP，文档格式可选 Markdown、PDF、Word。
- PDF 包含离线中文字体。PDF／Word 可嵌入 PNG、JPEG，其他文件仍作为原附件保留。
- 单篇导出最多涉及 100 个附件，附件与最终文件分别最多 50 MiB。
- 整库导出最多 2,000 篇（PDF 500 篇），有 200 MiB 的累计与最终文件预算。
- PDF 超过 8 列的表格用带行列标识的文字表达；不承诺逐像素重现编辑器。

导出经 Hermes 的原生下载入口保存。生成的临时文件最多保留一天，在后续导出时清理。

## AI 协作

开关默认关闭，位于笔记列表底部。开启后，agent 只能通过已注册的六个 Jot 工具搜索、读取、新建、更新、勾选任务及软删除。工具在开关关闭时也保持注册，因此打开开关后，已经打开的对话就能使用；关闭期间每次调用都会被拒绝，并提示在哪里打开。工具不能改变开关。

- **读取。** agent 以 Markdown 收到笔记，附带待办列表和当前版本，并告知用这段 Markdown 整篇重写是否会保留全部内容。
- **修改。** 精确修改只替换某个段落、标题、列表项、表格单元格或代码块里的可见文字，其余格式不动。追加内容加在末尾，新的待办会并入笔记末尾的待办列表。如果 Markdown 无法表达笔记的全部内容（例如图片、文件、颜色、下划线、调整过列宽的表格、嵌套列表或换行），整篇重写会被拒绝，除非用户同意丢失这些格式。每次修改都必须使用当前版本。
- **“让 Hermes 看这条笔记”**会把 `Jot note “标题” (id: …)` 放进对话旁的输入框；没有打开的输入框时复制到剪贴板。未保存的内容会先保存，保证 agent 读到的就是屏幕上的内容。
- **正在输入时。** 如果 agent 往你正在编辑的笔记末尾追加内容，新内容会并入你的草稿并继续自动保存；其他地方做出的其他修改仍会保留你的草稿，并让你选择如何处理。

列表及正文会标出 AI 修改。对已有笔记的一轮连续 AI 修改，可以恢复到该轮开始前的完整版本；人工改动后不再把旧的 AI 修改标记当作当前归属。AI 新建笔记没有“修改前”的版本。

Jot 不读取模型 Key，也没有独立模型请求。真正调用模型的是 Hermes。工具读取到的笔记是用户资料，不是能覆盖系统约束的指令。

## 存储、删除与卸载

持久化文件在当前 profile 的 `plugin-data/jot/`，插件目录里不存用户笔记。`jot.json`、备份、附件和 AI 撤销记录保持分离。卸载插件不会自动清理这些用户数据。

要把笔记搬到另一台宿主或另一个 profile，可以把整库导出为 Markdown，再在那边导入 ZIP（导出不包含的内容见“导入”）。如需包含置顶和 AI 记录的完整数据，仍要在没有写入时复制 `plugin-data/jot/`；不能直接覆盖另一个已有库。

## 桌面沙箱

富文本组件在 Hermes 官方的不透明来源沙箱里运行，不能读取宿主存储、密钥或原生桥，也不能自行联网。外层 SDK 组件负责经过验证的编辑消息、附件、文件保存和 profile 选择；不查询或修改 Hermes 的内部界面。

这个包使用一个预先构建的 Node 引擎处理笔记、导入和导出，按请求启动且不监听端口；导出和导入库只在对应请求时加载。需要 Node.js 22.19+；正常 Hermes 安装可通过官方 PM 准备依赖。导入文件暂存在 `plugin-data/jot/imports/`，每次请求结束后删除。

### 宿主预览兼容性

图片可直接显示；文档复用 Hermes 的文件预览入口，随记不再重复嵌入一份 PDF 阅读器。当前实测的 Hermes 版本支持 PDF，但 Word（DOCX）会提示二进制文件；Word 请使用“下载”或“用默认应用打开”。

## 主题

随记复用 Hermes 的背景、文字、边框、强调色、按钮、代码与提示气泡变量，并在宿主应用主题后同步到隔离编辑器，切换配色不需要重新打开笔记。产品图标保留品牌颜色；用户指定的文字与高亮仍属于文档内容，并在深色模式下做显示适配。实测覆盖 Nous、Solarized、Catppuccin 和 Cyberpunk；第三方主题自身的颜色对比度由其提供的变量决定。

## 收起与恢复侧栏

右键侧栏工具栏，使用宿主菜单的“最小化”收起；输入框旁的随记按钮可以恢复。Hermes 会保留一个区域的最后一个标签页，因此当随记是该区域唯一标签时，“隐藏随记”可能被宿主拒绝。展开工作台会带上当前草稿；两处对相同内容的重复保存不会误报冲突，不同的修改仍保留版本保护。
